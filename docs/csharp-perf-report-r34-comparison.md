# C# 编译器性能对比表（r34 节点，本轮实测）

> **元数据** ｜ 类型: report ｜ 日期: 2026-10-13 ｜ 轮次: r34-comparison ｜ 主题: three-way-comparison
> 数据来源: `bench/AB129`（r34 vs Go 默认）、`bench/AB130`（r34 vs Go@400）、`bench/AB131`（r34 vs C# 优化前基线）、`bench/AB132`（r34 vs r32 直接对批，跨批比值差异的对账批），每批 23 负载 × 15 组交替配对；分配侧为四个产品二进制在同一全量态直接运行（各 2 组）
> 环境: Windows 10 Pro for Workstations ｜ AMD Ryzen 9 8945HX（16C/32T）｜ 32 GiB
> 说明: 本表取代 r32 表成为当前口径。**"最新"节点为 r34**（git `d0ce61d61b`，sha256 前 16 `f735b05284e795fa`）：r32 全部改动 + r34 的对象字面量上下文路径五项（F1~F5），产物与 r32 产物在 medium/huge-file/真实工程三夹具逐字节一致（r34 为分配向改动，字节等价是预期）。

## 2. 分配对比（MiB，真实工程 326 文件，**全量 check + emit 态**）

| 节点 | CLR 总分配 | 相对上一节点 | 相对优化前基准 |
| --- | ---: | ---: | ---: |
| **C# 优化前基准（naot-svr）** | **1,221.7 MB**（两组 1,221,735,560 / 1,221,624,792） | — | — |
| **C# r28 节点（epsl-a1）** | **1,090.6 MB**（两组 1,090,603,168 / 1,090,622,904） | −10.7% | −10.7% |
| **C# r32 节点** | **1,005.2 MB**（两组 1,005,185,656 / 1,005,157,960） | −7.8% | −17.7% |
| **C# r34 节点（本表）** | **1,001.8 MB**（两组 1,001,847,768 / 1,001,752,456） | −0.34% | **−18.0%** |

**口径修正（重要，r34 发现）**：r32 表及其之前的分配列测于 **check 恢复态**（`--outDir` 兄弟状态文件 `<outDir>/../tsconfig.tsbuildinfo` 被后续运行读取，check 跳过、仅 emit；机制与规避方法见 `docs/csharp-perf-method.md` §7.1）。本表为全量态重测：同口径下四节点分别为 1,221.7 / 1,090.6 / 1,005.2 / 1,001.8 MB。恢复态读数（521.5 / 465.8 / 371.0 / 370.9 MB）只反映 emit 侧，节点间相对关系（−10.7% / −20.4%）仍有效但不是全量编译成本；累计改善的全量口径为 **−18.0%**（恢复态口径 −28.9%）。Go 侧 155 MiB 的 r15 口径（GOGC=off 提交峰值）未随夹具态重测，故本表不给"相对 Go 倍数"。

## 4. 已知例外（非回潮）

- tiny-files-noemit 对基线 −6.9%（CI [1.05, 1.09]）：r18 DATAS 关闭的既有代价，预算已知例外；r32 表该行 −12.8%，批间幅度不同、同向。
- host-paths x1.89：启动地板负载，substrate 差距（r30 定论，本仓不可修）。
- help 对基线 −2.3%（CI [1.01, 1.06]）、version −1.7%（CI 跨 1.0）：启动族在噪声带内的小幅波动，AB132 两行 1.013/1.031 同样不显著，不单独解读。
- 轻负载族的"改善"多在 CI 含 1.0 的不可分辨带内，不单独解读。
