## 2. 峰值内存对比（MiB，同批配对）

### 2.1 先读：跨会话不可比

同一二进制、同一夹具的峰值 RSS 在不同会话间相差可达 2.3 倍（`naot-svr` 在 medium 上：r13 期会话 125.8、r17 期会话 54.9、会话外单独测 92.8 MiB；批内 15 个样本各自紧密）。机制指向 DATAS 堆预算对机器内存状态的适应与操作系统工作集修剪。**下表只读批内比值（同批两槽位在相同机器状态下交替运行），不读绝对值，也不与任何历史会话的内存数字作趋势对比。**

本条对一个具体数字生效：r17 表曾记录"计算型负载相对 Go 的内存已反超（x0.85~0.94）"，该读数来自 r17 期会话（r17 在 medium 上 54.3 MiB）。同一配置在后续两个会话（AB92/AB93 与本次 AB95）都测出约 100 MiB，对应 x1.65~1.73。**r17 表的内存反超结论不成立，本表按批内比值重新记录。**

## 3. 相对 Go 的优势与劣势（r18 口径）

### 劣势（C# 慢于 Go 的 23/23 项）

| 维度 | 数据 | 归因 |
| --- | --- | --- |
| 单检查器重负载 | medium-checkers-1 **x2.07**（Go 默认）/ x2.23（Go@400），仍是 23 项最大差距 | 单 checker 串行时检查器本体最重；Go 同负载 102 ms，C# 219 ms |
| 巨文件 | x1.44 | 单文件 32K 对象字面量；并行 8 checker 时收窄到 x1.29 |
| 工程引用族 | x1.34~x1.58 | 多项目增量调度 |
| 轻负载启动 | x1.22~x1.32（version x1.22 最小） | 约 55 ms 的 Main 之前启动地板，占轻负载绝对耗时的 40%~85% |
| host-paths | x1.87 | 该负载诊断密集，C# 侧诊断生成路径慢（r17 表同项 x1.76，两代读数一致） |
| tiny-files-noemit | x1.30，且相对自身基准 −12.2% | DATAS 关闭后该形态的峰值内存涨 3 倍、耗时涨 12%（r18 报告 §3） |

### 优势（C# 不慢于 Go 的方面）

| 维度 | 数据 |
| --- | --- |
| 相对自身优化前基准 | 11 个重负载平均 **+45.6%**（区间 +25.4%~+59.7%，CI 全部不含 1.0）；巨文件 1,371 → 553 ms |
| 相对自身基准的峰值内存 | medium 族 6 项与 declarations 为基准的 0.70~0.79 倍（批内比值） |
| 诊断输出一致性 | 与 Go 基准在真实工程负载上诊断一致（均 0 行）；24 个夹具 + 12 个关系夹具产物逐字节一致（r15/r17/r18 门禁） |
| GC 配置红利 | r18 的 DATAS 关闭让重负载再快 14%~31%（r18 报告，两个全负载批次确认） |

**一句话概括**：r18 把 C# 对 Go 的重负载差距从平均 1.68 倍收窄到 1.46 倍，最好项（declarations x1.23、medium x1.26）已接近同一量级；剩余差距的主体是单检查器重负载（x2.07）与 55 ms 启动地板，内存侧则输在巨文件与 tiny-files 族（DATAS 关闭的代价，x1.9~3.6）。

## 4. 口径与批次有效性

| 批次 | 用途 | 同可执行文件控制项 `p95RelativePairDifference` | 控制项 medianRatio（CI） | 处置 |
| --- | --- | ---: | --- | --- |
| AB95 | r18 vs Go 默认 | 23.6% | 1.021（[0.882, 1.144]） | 采纳 |
| AB96 | r18 vs Go@400 | 20.2% | 0.925（[0.876, 1.161]） | 采纳 |
| AB97 | r18 vs C# 基准 | **45.0%** | 0.989（[0.962, 1.009]） | 采纳（理由见下） |

AB97 的 p95rel 超过历史判废线（r11 的 35.2%），但判废的实质依据是槽位偏置而非离散度：该批控制项 medianRatio 0.989、CI [0.962, 1.009] 紧且含 1.0，被检负载（medium、huge-file）15 个配对零污染、样本分布紧密（medium 基准 279~312 / r18 111~134，巨文件基准 1,346~1,415 / r18 542~585），改善 CI 与两个先前的独立批次（AB92/AB93 的 GC 效应）一致。高 p95rel 来自本机同时运行的其他进程对轻负载控制项的干扰。两槽外部 CPU 消费者基本对称（ZCode 累计量两侧同增）。

边界说明（沿用 harness 记录）：温文件系统、每样本新进程（含进程创建）；两后端用同一采集器测峰值 RSS 与进程 CPU；文件、诊断与发射字节逐字节比对，包版本头显式映射，运行时相关的 tsbuildinfo 版本从产物哈希中排除；受键鼠污染的配对保留并替换；256 MiB 负载对两个构建都使用 CLR GC 堆硬上限。三个批次均加 `--no-gc-env`：r18 报告已实测 GC 环境变量对该 AOT 产品无可测影响，该开关用于排除 harness 默认注入的干扰。
