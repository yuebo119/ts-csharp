## 1. 差距的源码级分解

### 1.1 分配侧（5.2×）的去向

r21 独占探针（真实工程，总 837 MB）给出的"自己分配"排名与源码定位：

| 帧 | 独占 | 调用 | 每次 | 源码定位（已读） |
| --- | ---: | ---: | ---: | --- |
| resolveMembers | 77 MiB | 37,508 | 2.1 KB | `InstantiateSignaturesAsync` 每表新数组、`Concatenate` 每基类新数组、未实例化表的必要字典拷贝 |
| checkerRelated | 42 MiB | 99,242 | 444 B | 无独立帧的 `normalization.RelationTargetAsync` + Simple/Weak 检查（需加子帧拆分） |
| typeFromNode | 36 MiB | 72,380 | 523 B | `CreateTypeReference` 的集合表达式数组 `[.. outer, .. args]`、`NodeArgumentsAsync` 列表 |
| symbolTypesGet | 32 MiB | 710,014 | 47 B | 每次约等于半条 `ValueSymbolLinks`（72 B，`LinkStore.Get` 首访问创建）；共享 lib 符号被每个 checker 各建一份链接 [推断] |
| variableType / objectCheckExpr / … | 各 16~21 MiB | — | — | 表达式检查本体（透传为主） |

节点对象本身**不是**差距来源：C# `IdentifierNode` 约 80 B（含 16 B 对象头 + 绑定槽），Go `Node` 约 48 B + 接口负载结构约 24 B ≈ 72 B，两者相当。5.2× 的大头是检查阶段的**临时分配**（闭包、字典、数组、状态机），Go 靠逃逸分析把它们留在栈上，.NET AOT 无逃逸分析全部上堆。

### 1.2 时间侧的三个组成

1. **单线程检查吞吐（最大项）**：检查器内层全异步（Checking 包 2,381 个 ValueTask 签名；r11 实测每个属性约 5 个 await 帧，巨文件 32K 属性）。net10（经典异步）比 net11（生产 runtime-async）慢 16%~41%，说明异步机制在这条路径上是真实成本；runtime-async 相对纯同步的残余税未单独测出 [推断：5~15%]。
2. **GC 与分配率**：r18 实测 GC 配置摆动能差 14%~31%，当前配置已是最优；r21 降 3.5% 分配对墙钟零可见，说明当前水位下边际不敏感。
3. **启动地板（约 55 ms，93% 在 Main 前）**：轻负载全部差距的主因，属运行时初始化，无代码级杠杆（r13 已定论）。

## 2. 方案（按投入产出排序，四层）

### 第一层 P：确定性修复（每项 1~2 天，合计预期 −40~70 MB 分配，墙钟 0~1%）

| # | 内容 | 依据 | 预期 |
| --- | --- | --- | --- |
| P1 | 给 checkerRelated 加 normalization / simple / weak 三个子帧，拆出 42 MiB 的构成再修 | r21 排名 #2 | 先归因后定 |
| P2 | `TypeArgumentsAsync` / `ClassReferenceAsync` 的 `[.. outer, .. args]` 数组改为复用 outer 数组前缀（多数引用 outer 数为 0，可直接传自有参数数组） | r21 排名 #3；`OuterTypeParameters` 已有 | −10~20 MB |
| P3 | symbolTypesGet：统计链接创建次数与共享符号的重复建链，评估"链接按符号唯一化（跨 checker 共享只读部分）" | r21 排名 #4；`LinkStore.Get` 每次可创建 | −10~25 MB |
| P4 | resolveMembers 剩余：`Concatenate` 传容量预估、`InstantiateSignaturesAsync` 空表返回缓存空只读集合 | r21 排名 #1 的余量 | −10~20 MB |
| P5 | `Symbol.Id` 惰性 Interlocked 改创建时赋值（RelationKey 哈希读 Id，115K+ 次键构造各读两侧） | `Symbol.cs:12-21` 与 `RelationKey.cs:19` | 墙钟微量，分配零 |

风险：全部是机械等价改写，逐字节产物门禁覆盖。

### 第二层 S：系统性分配（2~4 周，预期 −60~120 MB，墙钟 1~3%）

| # | 内容 | 依据 | 风险 |
| --- | --- | --- | --- |
| S1 | `RelationOperation` 池化（49,069 次分配、生命周期 = 单次顶层查询，可重置式复用） | r14 计数 | 可变状态（Explanation/suppressed）漏重置 → 诊断错误；需重置清单加安全套件 |
| S2 | 泛型关系键的 `List<Part>` + `Dictionary<Type,int>` 改 checker 级暂存池（1,218 次构造，量小但验证模式） | r14 计数 | 同上 |
| S3 | `mappingScratch` 模式推广：把 `TypeMapper.MapAsync` 里已验证的暂存栈模式（`Interlocked.Exchange` 归还）用于关系会话与成员解析的临时容器 | `TypeMapper.cs:77-97` 已有范例 | 模式正确性已被现有代码证明 |

注意：成员表字典**不可池化**（表的生命周期 = 类型的生命周期 = 整个编译期），此前想法作废，记录防止重提。

### 第三层 R：检查器同步化（1~2 月，唯一 >5% 墙钟杠杆）

r19 已给预判，本轮用新数据细化：

- **范围**：Checking 包 2,381 个 ValueTask 签名及其调用面；154 处 `TryEnsureSufficientExecutionStack + ForceYielding` 栈守卫。
- **前置设计（动工前必须）**：每个检查器组跑在自定义大栈专用线程上（.NET 支持指定栈大小），对应 Go 可增长 goroutine 栈；先写 10 分钟探针实测真实工程的最大递归深度，定栈大小（建议 256 MB 起步）。
- **分期**：自底向上（叶子模块先行），每层一次构建 + 36 夹具逐字节 + safety 全套；先转关系核心（relater/relations/session，约占检查时间 43%），**转完立即测墙钟，≥8% 才继续**，否则停在半程把已转部分作为净收益落地（r19 定的验收门槛沿用）。
- **预期**：回收 runtime-async 残余税 [推断 5~15% 重负载墙钟] + 状态机分配消失 [推断 −100~200 MB]。
- **同去的收益**：同步化后 P/S 层的池化更简单（无跨 await 生命周期问题）。

### 第四层 N：明确不做（防止重探）

| 项 | 理由 |
| --- | --- |
| AST 结构体 arena 重写 | 节点尺寸已与 Go 相当（§1.1），收益 < 巨额重写成本 |
| 跨 checker 共享关系结果缓存 | Go 亦未做；正确性依赖 checker 隔离假设，r16 已证单 checker 缓存健康 |
| AVX-512 / 裁剪开关 / 完整 LINQ | r20 三批实测零收益或更差 |
| 启动地板代码投入 | 93% 在 Main 前，运行时侧 |
| DATAS 混合形态（短进程保留） | 两个构建形态的发布成本，r18 已记录为可选后手 |

## 3. 量化预期与决策点

| 层 | 分配（837 MB 基线） | 重负载墙钟（x1.46 基线） | 投入 |
| --- | --- | --- | --- |
| P（全部） | −40~70 MB → ~780 MB | 0~1% | 1~2 周 |
| S（全部） | −60~120 MB → ~680 MB | 1~3% | 2~4 周 |
| R（关系核心起） | −100~200 MB | **5~15%**（门槛 ≥8%） | 1~2 月 |
| P+S+R 上限 | ~450~550 MB（约 3~3.5× Go） | **x1.05~1.25**（最好项接近 x1.0~1.1） | — |

两个诚实的天花板说明：

1. **分配到不了 1× Go**：节点/符号/类型图两边尺寸相当（合法工作），C# 侧无逃逸分析 + 对象头的 floor 约在 350~450 MB [推断]，P+S+R 已接近该 floor。
2. **轻负载差距（x1.22）任何层都动不了**：55 ms 启动地板占绝对主导。

### 建议的执行顺序与决策点

1. **先做 P1**（拆 checkerRelated 的 42 MiB）：一天内出结果，它同时是 P 层最大项和 R 层的情报（若 42 MiB 里藏着新的结构性缺陷，P 层收益上修）。
2. P2~P5 并行推进，一周收口。
3. **决策点（P 层完成后）**：若 P+S 预期合计 < 10% 分配且墙钟 < 2%，跳过 S 直接进 R；否则 S 做完再进 R。
4. **R 的 Go/No-Go（关系核心转完后）**：≥8% 墙钟改善继续全量；<8% 停在半程，把战果落地后本战役收官。
