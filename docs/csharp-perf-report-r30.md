## 0. 结论摘要

充分论证的结果是否定性的，且价值正在于此：**r29 的三项建议经实测定价后全部低于投入线**，战役遗留方向"host-paths 诊断归因"随之关闭。扩大扫描新增确认一个未测杠杆（GC 堆数）与两个低期望值待勘区，产品侧优化面就此逼近耗尽边界。

| r29 建议 | 论证方法 | 结论 |
| --- | --- | --- |
| P1 Kind 跳转表分派（原估 1~5%） | NativeAOT 微基准：25-case 链，类型链对跳转表差价均匀混合 +0.5ns/节点、单调热点种类 +2.7ns/节点 | **上限 0.02~0.3% 检查墙钟**（按 30~80 万次表达分量分派折算 0.15~2.2ms/编译）。现代 CPU 分支预测下顺序 `isinst` 链几乎免费。**不实施** |
| P3 Utf8String 缓存哈希（原估 1~3%） | 微基准：XxHash3 键 21.1ns/查找 对 缓存哈希 15.0ns 对 int 键 4.0ns | 缓存哈希省 ~6ns/查找 × 全部 Utf8String 键查找（~40~60 万次）= **上限 2.4~3.6ms ≈ 0.3~0.5%**，且构造期付哈希有净负风险。**不实施** |
| P2 诊断 params span（原估 1~3%） | host-paths 负载实测：5 文件/5,010 行/**1 条诊断**，check 0.002s + emit 0.005s，墙钟 0.203s | **host-paths 是启动地板负载**（196/203ms 为进程启动），非 r25 猜测的"诊断密集"。P2 目标市场不成立，降级为顺手卫生项（触碰诊断文件时一并改）。**战役遗留方向"host-paths 诊断归因"关闭**：x1.87 对 Go 是 .NET AOT 运行时初始化对 Go 二进制初始化的 substrate 差距，本仓不可修 |

## 1. 论证方法与原始数字

微基准工程 `C:\ai\projects\tsbench\dispatch-toll\`（镜像 `async-toll` 的基座属性，NativeAOT + Speed + ServerGC；与产品同 `System.IO.Hashing` 版本）：

**分派（每节点，1M 节点 × 200 轮）**：

| 形态 | Kind 跳转表 | 类型模式链 | 差价 |
| --- | ---: | ---: | ---: |
| 均匀 25 类混合（平均链位 ~13） | 7.85 ns | 8.31 ns | +0.46 ns |
| 单调热点（链位 16，模拟成段标识符） | 1.57 ns | 4.30 ns | +2.73 ns |

**字典查找（每次，4K 项命中，键 8/12/16 字节）**：XxHash3 重算键 21.1 ns；构造期缓存哈希 15.0 ns；int 键 4.0 ns。缓存哈希的收益全部来自省掉的重算（−29%），字典机械本体（探测+比较器调用 ~11ns）是 BCL 内部成本。

体量锚点（r28 真实工程 291 文件）：Identifiers 125,704、Symbols 64,392、Types 141,110、propertyLookup 284,135 次、symbolTypesGet 710,014 次、relationRelated 295,141 次。

论证要点：微基准给的是**无竞争上界**（无缓存效应恶化、无真实负载扰动），实际差价只会更低；即便按上界折算，P1/P3 都进不了噪声层（本机批次分辨率 ~±1.5%）。

## 3. 最终判断与 r31 建议

四轮透镜（r25 架构、r28 流程、r29 .NET 形状、r30 实测论证）之后，产品源码侧的优化面收敛为：

1. **r31 = GC 堆数轮**（唯一未测配置杠杆，方法：bake 4/8 堆 × AB × `GC pause time` 行直读；若有效则直接兑现 r26 停顿通道的全部剩余假设）。
2. 245 容器队列按频度分诊，作为每轮顺手批。
3. P2 params span 降级为顺手卫生项。
4. 其余方向维持既有否决清单；本轮新增否决：**P1 类型链→Kind 跳转表（实测 ≤0.3%）**、**P3 缓存哈希（实测 ≤0.5%）**、**host-paths 诊断归因（负载形态为启动地板）**。
