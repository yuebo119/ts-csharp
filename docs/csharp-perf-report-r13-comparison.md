## 3. r10 → r13 直接对照（口径修正）

r10 版对比表记录巨文件 C# 最新为 **822 ms**（比值 x0.556）。本轮在同期条件下测得的巨文件是 **669 ms**（比值 x0.476）。这个差额不能直接读作 r11~r13 的收益，因为两批的绝对量级不同（r10 批次基准 1,459 ms，本批 1,406 ms）。为消除批次口径，直接跑了一批 **r13 vs r10**（AB81，噪声 21.9%）：

| 负载 | r10 | **r13** | 变化 | 95% CI |
| --- | ---: | ---: | ---: | --- |
| **huge-file** | 657 | **609** | **+7.4%** | [0.891, 0.941] |
| medium-checkers-8 | 146 | 143 | +2.0% | [0.923, 1.007] |
| medium-256m-heap-setting | 122 | 120 | +1.7% | [0.968, 1.008] |
| medium-checkers-2 | 195 | 192 | +1.6% | [0.952, 1.040] |
| 其余 18 项 | — | — | −2.1% ~ +1.4% | 除两项外 CI 均含 1.0 |

结论：r11 + r12 + r13 三轮合计在巨文件上 **+7.4%（显著）**，其余 22 项在 ±2% 内。其中 r11 自己记录的巨文件 Emit −3% / Total −1%（AB76），r12 与 r13 同口径 Check 均无变化。因此 r10 版表里巨文件的 822 ms 属于慢条件批次下的读数，不宜与今日读数直接相减。

## 4. 口径与批次有效性

| 批次 | 用途 | 同可执行文件控制项 `p95RelativePairDifference` | 处置 |
| --- | --- | ---: | --- |
| AB78 | vs C# 优化前基准 | 22.8% | 采纳 |
| AB79 | vs Go 默认 | **12.9%** | 采纳 |
| AB80 | vs Go@400 | **14.8%** | 采纳 |
| AB81 | r13 vs r10 直接对照 | 21.9% | 采纳 |
| AB77 | r13 vs r12 | **166%** | **整批判废**，只取产物逐字节比对 |

AB77 判废的依据是同可执行文件控制项的 `medianRatio` 为 0.525：同一份二进制在 before 槽比 after 槽慢一倍，差异来自槽位所处时间段而非被测代码。该批次记录的机器活动显示运行期间有无关的持续 CPU 消费者（`PalDDD.Benchmarks` 835 CPU 秒、宿主进程 914 CPU 秒）。其余四批的外部 CPU 消耗都在几十秒量级。

边界说明（沿用 harness 记录）：温文件系统、每样本新进程（含进程创建）；两后端用同一采集器测峰值 RSS 与进程 CPU；文件、诊断与发射字节逐字节比对，包版本头显式映射，运行时相关的 tsbuildinfo 版本从产物哈希中排除；受键鼠污染的配对保留并替换；256 MiB 负载对两个构建都使用 CLR GC 堆硬上限。
