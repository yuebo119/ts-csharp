## 2. 峰值内存对比（MiB，同批配对）

### 2.1 先读：跨会话不可比

本轮测量中发现**同一二进制、同一夹具的峰值 RSS 在不同会话间相差可达 2.3 倍**：`naot-svr` 在 medium 上，AB78（r13 期会话）测 125.8 MiB、本轮 AB85 测 54.9 MiB、本轮会话外单独测 92.8 MiB；批内 15 个样本各自紧密（AB85 为 54.8~54.9）。机制上指向 DATAS 堆预算对机器内存状态的适应与操作系统工作集修剪，与产品代码无关（直接对照两种 `DOTNET_gcServer` 环境变量，同二进制托管堆 16.75 对 16.77 MB，无差异；产品编译期启用 Server GC）。

**因此：下表只读批内比值（同批两槽位在相同机器状态下交替运行），不读绝对值，也不与 r13 表或任何历史会话的内存数字作趋势对比。** r13 表"计算型负载为基准 0.78~0.83 倍、相对 Go 高 1.5~1.8 倍"的结论在本口径下不复现，也不被本表推翻。

## 3. 相对 Go 的优势与劣势

### 劣势（C# 慢于 Go 的 23/23 项）

| 维度 | 数据 | 归因 |
| --- | --- | --- |
| 单检查器重负载 | medium-checkers-1 **x2.26**（Go 默认）/ x2.46（Go@400），是全部 23 项的最大差距 | 单 checker 串行时检查器本体最重；Go 在同负载 104 ms，C# 232 ms。r14/r16 归因表明关系引擎与成员表的大帧已是合法工作本体，单点优化边际收益降至 0.07% |
| 巨文件 | x2.09 | 单文件 32K 对象字面量，检查阶段集中；checkers-8（并行 8 checker）收窄到 x1.61，说明并行度能回收一部分 |
| 轻负载启动 | x1.15~x1.34（version x1.15 为最小差距） | 约 55 ms 的 Main 之前启动地板，占轻负载绝对耗时的 40%~85%；这是运行时启动而非编译器代码 |
| 工程引用族 | x1.31~x1.55 | 多项目增量调度，每项目都要付进程内启动与程序构建 |
| 相对自身基准的轻负载回退 | 12 项中 7 项显著慢 1.9%~7.7%（绝对 1~4 ms） | 与 Go 差距同源：启动地板 + 每样本新进程；AB82（r15 vs r13）已记录同类待复核项 |

### 优势（C# 不慢于 Go 的方面）

| 维度 | 数据 |
| --- | --- |
| 峰值内存（本批同条件） | medium 族 6 项全部低于 Go 两个配置（x0.85~x0.94）；增量编辑 x0.69~0.75；noemit-on-error x0.85~0.87；巨文件对 Go@400 持平（x1.03） |
| 相对自身优化前基准 | 11 个重负载平均 **+36.8%**（区间 +22.6%~+47.8%，11 项 CI 全部不含 1.0）；巨文件 1,460 → 805 ms |
| 巨文件峰值内存相对自身基准 | x0.84（本批条件） |
| 诊断输出一致性 | 与 Go 基准在真实工程负载上诊断一致（均 0 行）；24 个夹具 + 12 个关系夹具产物逐字节一致（r15/r17 门禁） |

**一句话概括**：C# 版在重负载的计算吞吐上仍落后 Go 1.6~2.3 倍（单 checker 最差 2.26 倍），轻负载受 55 ms 启动地板压制落后 1.15~1.55 倍；但在中量级负载的峰值内存上已反超 Go（x0.85~0.94），且相对自身优化前基准重负载快 36.8%。差距的主体已从"可修的分配缺陷"转为"检查器本体的吞吐与运行时启动"。

## 4. 口径与批次有效性

| 批次 | 用途 | 同可执行文件控制项 `p95RelativePairDifference` | 控制项 medianRatio（CI） | 处置 |
| --- | --- | ---: | --- | --- |
| AB83 | r17 vs Go 默认 | 21.2% | 0.977（[0.926, 1.020]） | 采纳 |
| AB84 | r17 vs Go@400 | 19.6% | 1.015（[0.909, 1.111]） | 采纳 |
| AB85 | r17 vs C# 基准 | 18.0% | 1.017（[0.985, 1.038]） | 采纳 |

三批的控制项 CI 均含 1.0，槽位间无系统性偏置；批内样本分布紧密（如巨文件 r17 的 15 个样本落在 791~861 ms，配对比值 2.02~2.20）。外部 CPU 消费者在三批两槽之间基本对称（ZCode 进程累计量两侧同增，AB85 的 after 槽另有一个 81 CPU 秒的音频软件进程，量级远低于控制项分辨率）。

边界说明（沿用 harness 记录）：温文件系统、每样本新进程（含进程创建）；两后端用同一采集器测峰值 RSS 与进程 CPU；文件、诊断与发射字节逐字节比对，包版本头显式映射，运行时相关的 tsbuildinfo 版本从产物哈希中排除；受键鼠污染的配对保留并替换；256 MiB 负载对两个构建都使用 CLR GC 堆硬上限。本表 C# 节点的 GC 环境变量为 Workstation（harness 默认），直接实测确认该环境变量对编译期启用 Server GC 的 AOT 产品无影响（托管堆 16.75 对 16.77 MB），因此与 r13 表批次（环境变量为 Server）的计时口径一致、内存绝对值不可比（§2.1）。
